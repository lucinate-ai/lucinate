### S2 — rozwinięcie

**AUD-001 — README prowadzi Hermesa w URL, który kod odrzuca.**
`README.md:83` opisuje backend jako „`/v1/responses` API server", a `README.md:85` mówi wprost: „OpenAI-compatible and Hermes URLs are HTTP(S) base URLs ending in `/v1`". Tymczasem `internal/backend/hermes/backend.go:235-243` uznaje za legacy każdy path zawierający `/v1`, a `Connect` (`:251-253`) zwraca wtedy `legacyEndpointHint`; `openspec/specs/backend-hermes/spec.md:179-184` czyni to zachowanie wymaganym (SHALL fail). `docs/backend_hermes.md:14` i spec `:11` mówią poprawnie: WebSocket `/api/ws`, port 9119. Skutek: użytkownik instalujący wg README nie połączy się i dostanie komunikat o „legacy API server", czyli sprzeczny z instrukcją, którą wykonał. Zawężenie: sam formularz TUI jest poprawny — preset Hermesa prefilluje `http://localhost:9119` (`internal/tui/connections.go:436,475-478`), a w kodzie nie ma placeholdera z `/v1`; sprzeczność jest wyłącznie w README (plus etykieta pola „Base URL:" jest współdzielona z OpenAI, `internal/tui/connections.go:175-178`, co tę pomyłkę podtrzymuje). Naprawa: dwa zdania README; opcjonalnie etykieta.

**AUD-002 — anulowany turn nigdy się nie „settluje".**
`StreamsFor` (`internal/rooms/stream.go:109-150`) zdejmuje strumień dla `message.member`, `turn.settled`, `turn.failed`, `turn.deferred`, `member.unavailable` — `turn.cancelled` nie ma w tej liście, więc `ActiveStreams` (`internal/rooms/stream.go:122-131`) zwraca tego członka jako odpowiadającego. TUI liczy z tego spinner (`internal/tui/rooms_ux.go:200-206`), a renderer cancelled row obsługuje (`internal/tui/rooms.go:2335`) — użytkownik widzi „przerwano" i jednocześnie animowany wiersz „odpowiada" bez końca. Zawężenie (sprawdzone): `DiscussionBudget` (`internal/rooms/discussion.go:146-179`) też nie zdejmuje `openTurns`, ale obie gałęzie switcha dają dziś ten sam wynik (`EndReasonNone == ""`, `Ended == false`), więc to defekt utajony, nie drugi objaw. Wysyłanie działa — composer nie jest blokowany; fałszywy jest stan wiersza. Test istnieje tylko na render (`internal/tui/rooms_composer_test.go:174-204`), nie na stan strumienia. Naprawa: `turn.cancelled` w `StreamsFor` + test regresyjny na `ActiveStreams`; `DiscussionBudget` dla symetrii (i żeby przyszła zmiana nie ożywiła licznika).

**AUD-003 — „200 bez SSE" jest raportowane jako sukces.**
`runStream` (`internal/backend/openai/backend.go:355-390`) sprawdza tylko `StatusCode >= 400`; nie sprawdza `Content-Type`, a każdą ramkę, której nie da się sparsować, ignoruje (`return false`). `ScanSSE` (`internal/backend/httpcommon/sse.go:26-38`) przepuszcza tylko linie `data: `, więc odpowiedź HTML 200 daje zero zdarzeń, czysty EOF i `EmitChatFinal(runID, sessionKey, "")` — bez błędu, bez logu, bez wpisu asystenta w historii (użytkownik zostaje z osieroconym turnem w `history.jsonl`). Scenariusz: zły base URL, proxy, captive portal, endpoint zgodny tylko z nazwy. Naprawa: wymagać `text/event-stream` albo co najmniej jednej sparsowanej ramki; licznik odrzuconych ramek do błędu.

**AUD-004 — brak timeoutu na nagłówki i na ciszę w strumieniu.**
`ChatSend` tworzy `streamCtx` z `context.Background()` (`internal/backend/openai/backend.go:294`), a transport (`internal/backend/httpcommon/client.go:124-139`) ogranicza tylko dial i TLS — komentarz w `:124-126` świadomie zostawia odczyt bez limitu. `main.go:11` podaje `context.Background()`, więc `lucinate send` czeka w `app/send.go:214-230` bez deadline'u; serwer, który przyjmie TCP i nie wyśle nagłówków, wiesza proces (Ctrl+C zabija bez cleanup, bo nie ma `signal.NotifyContext` — 0 trafień w repo). TUI ratuje się abortem (`b.runs[runID]`), CLI nie ma czym. Naprawa: `ResponseHeaderTimeout` + idle-timeout między ramkami + domyślny `--timeout` dla `send`/`ask`.
